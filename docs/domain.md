# 领域说明

可转债判断依赖债券条款、正股价格、转股价和市场交易日。强赎、回售、下修与
转股价调整可能使用不同观察窗口，也可能互相影响后续计算。行情补发、公司
行动和公告撤回都需要形成新的可追溯数据版本，历史研究结论应保留引用依据。

`reference/domain.json` 保存可公开的示例枚举与精度约定。正式业务记录应使用
稳定标识，并区分业务发生时间、系统接收时间和记录版本。

## 版本与回放模型

- 每类业务实体（条款、行情、除权、停牌、下修、交易日历）都是追加式记录：
  每次修订产生递增的 `record_version`，并带全局 `ingest_seq` 与接收时间
  `ingested_at`；记录一经写入不可变更，撤回以新版本 `status=withdrawn` 表达。
- 行情的正式价（`official_close`/`corrected`）与盘中临时价（`temporary`）
  是两条独立版本线，临时价不会顶掉正式价。
- 每次评估生成判断版本：内容哈希去重，证据（逐日比较、排除原因、数据缺口）
  与输入清单（各实体版本 + `as_of_seq` 回放游标）一并持久化。
- 结论引用（`references`）指向具体判断版本；出现更新版本时旧引用被圈出
  （`stale`）并附差异摘要，旧版本本身永不覆盖。
- 回放以 `as_of_seq` 复原当时可见的全部记录重算，校验内容哈希一致。

## 计算顺序约定

- 转股价时间线由记录驱动：初始价 → 除权事件（按公式调整）→ 已批准下修
  （绝对定价）。同一生效日除权先于下修；条款评估本身不改写转股价。
- 条款间的相互影响（观察期被其他条款触发截断、显式 `depends_on`）经依赖图
  拓扑排序给出确定性评估顺序；循环依赖在条款登记时即被拒绝。
